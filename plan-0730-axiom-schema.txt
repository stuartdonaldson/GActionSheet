2. WHAT IT UNCOVERED: Axiom 'nuuts' dataset at its column-count cap
-------------------------------------------------------------------------------
Investigating why `reset_test_state`'s own GasLogger.log call silently failed
to appear in Axiom queries led here. The 'nuuts' dataset had hit Axiom's
256/257-field-per-dataset schema limit (bead gts-pfyx, closed 2026-07-29,
which only implemented the "surface failures loudly" stopgap -- the real fix,
restructuring the row shape, was explicitly left undone).

Root cause: GasLogger.js's `_postToAxiom` used to spread every GasLogger.log()
call's second-argument object as TOP-LEVEL Axiom columns
(`Object.assign({_time,name,side,app,version}, e.data)`). ~100+ call sites
across the codebase, each with different field names, permanently grew the
schema. Worse: `WebApp.js`'s `markedByDocId` object was keyed BY DOCUMENT ID
(`markedByDocId[docId] = count`) -- every new document ever seen minted its own
column, unbounded. This was the single biggest contributor (~89 of the
observed columns were `markedByDocId.<docId>`).

    while every other call site in the codebase uses `globalId` (camelCase),

    `globalId` -- the wire contract (`payload.global_id`, JSON response
    `global_id`, scn/session.py's `_post_route(..., {"global_id": ...})`) is
    UNTOUCHED. Grepped every GasLogger.log() call site afterward; confirmed no
    other snake_case field names remain anywhere in src/*.js.
  - scripts/query_axiom.py `_print_table`: updated to unpack the new nested

(b) CODE WRITTEN, NOT YET DEPLOYED (this is the actual state to resume from):
  - src/Version.js: added `env: "test"` to the BUILD_INFO object literal
    (placeholder default; gets overwritten by manage-deployments.js on the
    next deploy of any target).
  - manage-deployments.js `stampVersionInfo(target, url)`: now also computes
    `env` ('test'/'dev'/'production' from `target`) and writes
    `env: "<env>"` into Version.js alongside the existing version/buildDate/
    webappUrl stamps. Comment explains env is the source of truth going
    forward; the "(TEST)"/"(DEV)" suffix on the human-readable `version`
    string is a derivative of it, not the other way around.
  - src/GasLogger.js `_postToAxiom`: two further changes on top of (a)'s
    nesting, NOT yet deployed:
      1. `env` is now a real top-level Axiom column, read from
         `BUILD_INFO.env` (falls back to `'unknown'` if absent). Rationale:
         previously the only way to filter test vs prod logs was substring-
         matching the free-text `version` field ("... (TEST)") -- this makes
         it a clean equality filter.
      2. `docId` / `docIds`, when present in a log call's data object, are
         HOISTED to real top-level columns and REMOVED from the nested `data`
         copy (single source of truth, no drift). Rationale (user-driven):
         "every event touching document X" is the single most common
         cross-event query shape, and a single `docId` column with many
         distinct VALUES is fine -- it is NOT the markedByDocId anti-pattern,
         which minted a new COLUMN per value, not a new row-value in one
         column. This is a deliberate, explained distinction worth
         re-confirming out loud with the user if picking this back up, since
         it's easy to conflate the two.
  - scn/reporter.py: added `"env": "test"` (hardcoded, with a comment
    explaining why -- ScenarioSession/Reporter only ever talk to
    webappTestUrl today; promote to a real parameter if that ever changes) to
    both Axiom row-construction paths (`emit_standalone_event` and
    `Reporter.event`'s buffered path), for symmetry with GasLogger.js's new
    top-level `env` column on the GAS side.
