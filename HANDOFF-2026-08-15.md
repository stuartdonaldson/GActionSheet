# Handoff — export folder isolation (gts-z6j0/gts-es3l) + gts-lirp instrumentation — 2026-08-15

## Where this session started

Continuation of `tmp/pr3-pr4-combined`. Picked up from
`HANDOFF-2026-08-14.md`'s architecture discussion: governance-exporter output
(JSON export, PDF snapshot, and future image-extraction artifacts) was
landing in the source document's own parent folder via `getSourceFolder_()`
— visible to every user with access to that folder alongside the real
document. User asked for options; picked **a well-known export root folder,
one subfolder per exported document**, pushed via `local.settings.json` +
Script Properties (same pattern as `webappSecret`/`axiomToken`), with a
docId-keyed index sheet (not name-keyed, since document titles collide) that
can also carry other small per-export metadata later.

### 2. gts-lirp instrumentation (not yet exercised against a live flake)

Discussion (not code) walked through why a blind delay/retry is the wrong
fix for `gts-lirp` (Import-tab `read_import_list()` intermittently returns
`[]`): the bead's own diagnosis already found **two distinct failure
modes** under the same symptom — (1) no server round trip at all (stale
click), (2) round trip succeeded but the DOM read raced a stale render — and
a fixed delay can't tell them apart or guard against masking mode 1.

**Implemented in `scn/ui.py`** (additive, no existing test semantics
changed):
- `UiDriver.__init__` gained `_last_show_tab_fence`.
- `show_tab()` captures a log fence (`tests.helpers.gas_log.clear_logs`,
  lazy-imported, best-effort/never breaks the click) immediately before the
  click.
- `read_import_list()` refactored so its DOM-parsing loop is a nested
  `_parse()` callable twice; when the initial parse comes back empty **and**
  a fence was captured, calls new `_diagnose_empty_import_list(frame)`:
  - No `importList.done`/`importList.access_denied` log event after the
    fence → **mode 1** → raises with a `capture_failure()`-backed
    diagnostic (screenshot + frame probes, same convention as every other
    bounded-wait failure in this driver).
  - Event found with `count == 0`, or `access_denied` → confirmed
    legitimately empty → returns `[]` exactly as before (unchanged for the
    P4/TeamNotFound-style tests that expect a real empty result).
  - Event found with `count >= 1` → **mode 2** → one evidence-gated 2s
    settle retry, re-checks the DOM; if now populated, re-parses and
    returns the real data (self-healed); if still empty, raises with a
    distinguishing diagnostic instead of a silent wrong `[]`.

This reuses 100% existing infrastructure (`tests/helpers/gas_log.py`'s
Axiom-backed `clear_logs`/`collect_logs`, already used elsewhere in
`tests/test_import.py` via `assert_log`) — no new GAS-side code was needed.
`node --check`/`py_compile` both clean. **Not yet exercised against a real
occurrence of the flake** — gts-lirp is intermittent, and it didn't recur in
today's (degraded, see below) sweep. Next time `test_import_access_filter`
or `test_import_flow_forward_sync` fails, the failure message itself should
now say which mode fired instead of the current opaque "expected X, got
[]".

**No deploy needed for this change** — it's Python-only test-harness code.
